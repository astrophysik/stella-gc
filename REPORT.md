## Алгоритм и устройство реализации

Основной алгоритм - неперемещающий mark-and-sweep. Выбранное расширение - инкрементальная маркировка: сборщик выполняет часть работы перед выделениями памяти, чередуя её с выполнением программы в одном потоке.
Все выделенные объекты учитываются в связном списке allocations. Достижимость определяется от динамических и постоянных корней. Обход учитывает только managed-поля, число которых задаётся дескриптором объекта.
Маркировка использует три цвета, хранящиеся в gc_word: белый — объект ещё не обнаружен, серый — обнаружен и ожидает сканирования, чёрный — полностью просмотрен. Серые объекты хранятся в отдельном динамическом стеке (grey_objects). Объект добавляется в стек только при переходе из белого в серый.
Основной инвариант маркировки: чёрный объект не ссылается на белый объект управляемой кучи. Барьер записи сохраняет его: при записи ссылки в чёрный объект белый целевой объект становится серым. Барьер применяется при обычной записи и изменении раскладки объекта. Каждый объект сканируется целиком без возврата управления программе.
Корни просматриваются в начале цикла и повторно после опустошения серого стека, поскольку присваивания корневым переменным не проходят через барьер записи.

## Параметры

Параметры задаются в виде define через -D при сборке

GC_MARK_STEPS - кол-во объектов для обработки на каждом шаге mark фазы, значение по умолчанию 5, возможные значения [1, 2, ...]
GC_HEAP_THRESHOLD - порог начала цикла сборки мусора, значение по умолчанию 0.75, возможные значения [0.0, ... 1.0]

## Тестирование

Есть несколько C тестов и Stella тестов.
/tests/c/cycle - проверяет сборку цикла
/tests/c/fields и /tests/c/update - проверяют базовую работу сборщика 
/tests/c/write_barrier - проверяют корректность работы барьера на запись и покрас объекта в серый в stella_gc_write_managed
/tests/c/update_marking - аналог write_barrier только для изменения через функцию stella_gc_update_object

Не уверен на счёт корректности пункта с реализацией алгоритма пометки без стека. Сейчас присуствует стек серых объектов 

Есть неточности в проверки глобальных переменных GC_MARK_STEPS, GC_HEAP_THRESHOLD

Инкрементальная только маркировка, но так было и на лекции
